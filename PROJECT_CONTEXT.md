# second-brain-researcher: decision history

Why the plugin is the way it is: the decisions of past sessions, with the reasoning and the measurements behind them. Current rules live in `CLAUDE.md`; this file explains them. A decision that was later reversed is deleted rather than struck through (git history keeps it). One paragraph per line: search it with `grep -n`, read entries by line range.

## Motivation

Methods relevant to a problem often already exist in an adjacent field, but finding them is manual and ad hoc, and whatever is found rarely gets captured anywhere durable, so the next project starts from zero. Example: MedDINOv3 embeddings underperformed on sarcopenia CT without finetuning, for reasons (CLS-token pooling losing texture signal, the domain gap from natural-image pretraining) that were already documented in the literature; nobody was searching for it systematically.

## Not built yet

The original spec has 7 stages; 1–5 are built, and stage 6 only in reduced form. Still to come:

- **Stage 6 in full:** similarity over full text rather than title and abstract, and linking across problems (a paper relevant to two projects' vaults). The profile fields for cross-project linking were removed on 2026-09-25 because intake asked about them and nothing used them; re-add them with the feature.
- **Repo cloning and analysis after the checkpoint:** clone approved repos into `code_vault/<id>/`, summarize their structure and classes, and optionally run or test them in a local Docker sandbox isolated from production data.
- **Stage 7, the experiment plan:** propose a baseline and ideas from the vault, and adapt code from the repo vault into the researcher's existing project repo, not a new one.

## Architecture

- **Agent vs. skill.** A piece is a skill only if it needs the main conversation: `research-problem-intake` runs a live Q&A, `second-brain-pipeline` holds the stage-4 checkpoint across a real turn, and `second-brain-topic-deep-dive` may have to ask which vault or note is meant. Everything else is an agent, with a `tools:` allowlist the system enforces, or a script when no model is needed. A dispatched agent runs once and returns, so it cannot pause for an answer: any instruction telling one to "ask" is a bug, and every input it needs is passed explicitly by the pipeline. The vault writer began as a skill whose body was "dispatch a subagent", became an agent (`obsidian-vault-writer`) so its tool scope was enforced, and then became `scripts/build_vault.py` once it turned out to need no model at all.
- **Every agent's `description:` warns against being reimplemented or routed around.** It is the only text an orchestrating session sees before dispatch, and a session once treated a subagent's correct "needs a restart" report as license to do the job itself.
- **Model tiers are pinned per agent, never `inherit`.** Per-item and mechanical work runs on `sonnet` (the discovery legs, `paper-summarizer`); only `topic-summarizer`, the cross-paper synthesis and equation extraction, runs on `opus`. `inherit` would tie synthesis quality to the main session's model, and would silently run 30+ summarizer dispatches on Opus when the main session is Opus.
- **One copy of each schema.** The `templates/` files are the only definitions; an early vault skill restated the profile and paper-note schemas in its own reference files, and since the vault stage's input is the summarizer's output, any drift would break the handoff silently. The one sanctioned copy (2026-09-25) is intake's YAML skeleton of the profile: the main conversation would otherwise have to read the whole 19 KB spec, which costs more than the copy. The `schema-copies` offline suite fails when the two drift.
- **Token spend: cost is turns × context, and deterministic work moves to scripts (2026-09-24).** The 42-paper reRD run cost 20.8M weighted tokens (input + 1.25 × cache write + 0.1 × cache read + 5 × output, summed by `scripts/token_report.py`). The harness's per-agent token figure is only the final context size. The split: the vault-writer agent 25% (63 turns over up to 670k of context, for a job with no judgment in it), `topic-summarizer` 22% (213 of its 392 Reads were summaries), `paper-summarizer` 20%, the main conversation 16%, discovery 17%. What changed: the vault writer became `build_vault.py` (same sections in all 83 notes, 0 dead links of 802, byte-identical BibTeX); `stage_prep.py` replaced the main conversation's file reads with compact reports; fan-outs go in foreground waves with template prompts and `OK`/`FAIL` replies; `paper-summarizer` batches short papers and stops at the references; `topic-summarizer` reads one digest per topic and has a fixed full-text budget. Deliberately not done, since each could weaken the results: cutting search breadth, word caps on summaries, changing model tiers, inlining the profile into dispatch prompts (a dispatch prompt is re-read on every later turn of the main conversation, so twenty inlined 5 KB profiles cost more than twenty small Reads).
- **Waves.** `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20) refuses a call past it rather than queueing it; reRD lost 9 of one message's 14 dispatches that way. Raising it saves wall-clock time, not tokens.
- **Each problem is its own Obsidian vault (2026-09-24).** Links used to be written as `[[<problem-id>/papers/<id>]]`, correct only for a vault opened one level up. The researcher opened `obsidian_vault/<problem-id>/`, the natural choice, and all ~800 links of a 42-paper vault were dead. Links are now written from the problem folder, and `check_vault.py vault` resolves every link the way Obsidian does after each run. One vault no longer spans problems, which nothing used.
- **A paper's id is its filename stem, fixed at download (2026-09-24).** The same paper used to carry three ids (the downloader's from the authors, the summarizer's from the title, the code leg's from the filename), and the vault writer repaired the resulting dead links by matching titles. Now every stage uses `YEAR_first_second`, computable from a path, and an unknown id is reported, never title-matched. `check_vault.py records` checks id agreement before the vault is written. Vaults built before this have old ids, and the topic deep-dive refuses them.
- **Vault build needs neither Obsidian nor its REST API.** A vault is a folder of Markdown. Merge-on-rerun is plain file I/O: `build_vault.py` splits a note into frontmatter and `##` sections, regenerates the sections it owns and keeps everything else. The Obsidian Local REST API was planned for this and rejected: it writes into whichever vault Obsidian has open (a mismatch would misplace a problem's notes silently), and needs a token, a community plugin, a running app and a self-signed certificate. Reconsider only for something that needs Obsidian's own link resolution. Opening the vault is an optional last step; installing Obsidian is out of scope (the old auto-install was `winget`-only).

## Plugin mechanics

- **`arxiv-mcp-server` is a declared dependency, verified live.** The `dependencies` field auto-installs and enables it, even self-healing a failed install without a restart, but only once its marketplace is registered; it does not add the marketplace itself. Without the dependency, Claude Code refuses to load this plugin at all, under a real install and `--plugin-dir` alike, so no agent re-checks it.
- **MCP tool names under both prefixes.** A plugin-bundled server's tools are `mcp__plugin_<plugin>_<server>__<tool>`, a user-level one's `mcp__<server>__<tool>`. The agents first named only the plugin form, and on a machine where `arxiv` was a user-level server they silently had no arXiv tools: an allowlist naming a missing tool raises no error.
- **`paper-search-mcp` is bundled in `.mcp.json`, not a dependency.** `dependencies` accepts marketplace plugins only, and it is not one (it ships a PyPI package and a Skill); declaring it would stop the whole plugin loading.
- **Keys come from the environment only.** Claude Code does not read `.env`, and an unset variable with no default is substituted literally into `.mcp.json`, hence `${VAR:-}` everywhere. The cross-field agent checks its key itself, so the pipeline never needs to know about credentials, and a skipped optional leg is never a failed run.
- **The home repo is `BartvanderWoude/second-brain` (2026-09-25).** It replaced `ofulla/second-brain-researcher`; the marketplace and plugin names stay `second-brain-researcher`, so the install command did not change.

## Discovery

- **Paywalled papers: open access first, then Sci-Hub, by operator decision.** The original rule flagged paywalled papers for manual download. The operator chose Sci-Hub as the last rung instead: open-access rungs run first (faster, more reliable, better extractions), Sci-Hub only for what they cannot resolve, a dead mirror counts as unresolved rather than absent, and whatever resolves nowhere lands on a needs-manual-download list the stage-4 checkpoint stops on. Sci-Hub is legally contested, and the plugin is public, so the behaviour ships to everyone who installs it; worth re-weighing.
- **Full text comes from `fetch_fulltext.py`, not `download_with_fallback` (2026-09-24).** On the 42-paper run 16 of 20 clinical papers ended up abstract-only through `paper-search-mcp`'s fallback: PMC called open-access papers closed, Europe PMC's PDFs returned 403 (twice saving the HTML error page as `.pdf` while reporting success), CORE failed on every DOI, and the Sci-Hub mirror did not resolve. The script's rungs: Europe PMC full-text XML (JATS straight to Markdown, so no PDF and no garbled digits; one Docling output had rendered `0.90` as `Ͷ.ͿͶ`), NCBI BioC for NIH author manuscripts (Europe PMC's XML answers those with a 500), the arXiv PDF, Semantic Scholar's open-access PDF, Unpaywall. It fills missing ids from Semantic Scholar first, and refuses any download not starting with `%PDF-`. Four papers from that run that had no text all came back full. The same run lost 17 arXiv papers to `arxiv-mcp-server` lacking its `[pdf]` extra; that error is now permanent (no retry) and the paper goes to the arXiv-PDF route.
- **Every saved paper has an identity header (2026-09-24).** arXiv files used to be bare copies of the MCP cache, so 16 of 42 summaries had no identifier and Semantic Scholar embedding coverage fell to 26/42; nine "full texts" were really note-shaped records or abstract stubs. Now every leg writes the header in `templates/paper-identity-spec.md` from the source's metadata, `full_text` says which kind of body follows, and the body is never summary-shaped. The spec's key ladder starts at DOI because every non-arXiv source supplies one; a title match with different DOIs is the preprint/published pair. Cross-leg duplicates are merged by `stage_prep.py merge` before the checkpoint, since the parallel legs cannot see each other's writes.
- **`paywalled` describes the paper, `full_text` the fetch.** `paywalled: true` means no open-access copy exists, even when Sci-Hub then supplied one. The first biomedical agent marked papers paywalled because its own capture failed; an open-access paper that merely hit a missing Docling is `paywalled: false`, or the researcher hunts for a subscription they already have.
- **Docling flags, measured.** The default embeds figures as base64: one Europe PMC paper came out at 545 KB with a single 200,132-character line, against 56 KB with `--image-export-mode placeholder` and the same structure. `--no-ocr` cuts 49 s to 10 s on born-digital PDFs; output under 10 KB means a scanned PDF and is retried with OCR.
- **Silent failures, handled in prose.** Several tools succeed while returning something wrong, and only the instructions stop that becoming a false finding: arXiv's search over-restricts two ANDed quoted `abs:` phrases to zero hits; `search_paper_text` matches literal substrings, so a natural-language query returns success with zero passages (read as "the paper doesn't discuss it"); `read_pubmed_paper` returns an apology string shaped like content and `download_pubmed` raises `NotImplementedError` (both now left out of the allowlist); Asta without a key hangs (next entry).
- **Asta's key is effectively required, despite its docs.** Tested keyless: `initialize`, `tools/list` and identifier lookups work (`search_paper_by_title` in 32 s), but `snippet_search` and `search_papers_by_relevance` each hang ~271 s and fail with `RetryError[ConnectionRefusedError]`, reproduced twice per tool. With a key, `snippet_search` answers in ~31 s. A missing key reads as a network fault, so the agent checks the key before any search. `snippet_search` takes no date range (only `inserted_before`), so the cross-field pass is not date-bounded.
- **No `[MeSH]` tags by default, measured.** Automatic Term Mapping already ORs a bare term with its MeSH descriptor, so an explicit tag only narrows: 1378 hits against 3567 untagged, and 532 against 1296 over the last two years. Indexing lags publication, so mandatory MeSH drops the newest work.
- **PubMed's date window lives in the query string.** The MCP search has no date parameter, and `search_papers`' `year` applies to Semantic Scholar only; `find_papers.py --window` appends a `[Date - Publication]` range clause instead.
- **Core coverage: the core question is covered exhaustively (2026-09-24/25).** An audit of the reRD run: of 19 papers squarely on its core question (15 found by a well-built query, plus 4 classical PVR prediction papers), the run had 5. Replaying the PubMed leg's 21 queries: 8 missing papers matched no query (queries were bare word lists, which PubMed ANDs; the only core query used `machine learning` as its sole method term, and its retry dropped `nomogram` and `risk score`); 3 ranked below the top 30 the leg read (Gan was #46 of 54; the MCP search reports no total and cannot page); 3 were retrieved but lost their slots, 20 being split evenly over 6 questions. The same concepts as three concept blocks returned 41 hits with all four closest comparators in them. One hop of citation chasing from the 10 core papers found recovered 10 of the 14; PubMed's "similar articles" recovered 1 of 10. Semantic Scholar returns empty reference lists for many clinical publishers (0 where OpenAlex has 35 and 29), so chasing uses OpenAlex. A first fix, a stage-4 recall check with a numbered pick-list, was superseded the next day. What stands: `core_questions` in the profile (uncapped in the legs, background capped at 20); `find_papers.py pubmed` fetching whole hit sets and flagging a query over 300 hits instead of cutting it; concept-block query rules, with classical and ML method terms together and retries that widen; and the citation chaser, running the recall probes and then chasing one hop both ways until a round adds nothing, stopping at 4 rounds or 40 additions in a round.
- **The chaser's live run on a copy of the reRD vault** took 36 turns and 1.20M weighted tokens (about 6% of the original run). It chased three rounds from 6 seeds and added 32 papers, recovering 11 of the 14. Fixed after it: a multivariable analysis of predictors now counts as classical prediction work (it had rejected Kon 2000 and Burton 1977), drafted probes cover every outcome the core question takes in (it had missed Xing, a PVR nomogram), and `add` refuses a candidate number passed with the wrong list name (it had saved an unrelated paper that way). OpenAlex's keyless budget is about 1,000 filter requests a day; a round takes about ten.
- **Code discovery is API-only, so it runs before the checkpoint.** `gh api …/readme` and `…/git/trees/<branch>?recursive=1` supply everything a repo note needs, with nothing written to disk; a cloning leg could not run before the researcher approves anything. It runs after the paper legs because its best source is the repos the saved papers name (41 URLs across 35 cached papers). License and provenance do most of the screening: an empty license means no reuse rights, and a 40-star repo linked from the paper beats a 3k-star reimplementation.

## Vault build

- **Paper links come from a script (2026-09-24).** A `similarity-linker` agent was evaluated on a 12- and a 41-paper vault, Haiku and Sonnet, two runs each, against ground truth from Semantic Scholar: both had 100% precision but found almost none of the bibliographic couplings that make up most of the graph (355 candidates against 37 direct citations on 41 papers); Haiku found 0–4% and wrote one-way edges, Sonnet 0–61% at $3–4 a run. `link_papers.py` scores 100% for no model cost, from one Semantic Scholar batch call (references and SPECTER2 embeddings, 3 s for 41 papers). Links: direct citations; shared references (at least 2 outside the vault, since one shared benchmark paper would link everything); similar content (cosine ≥ 0.90, only without a citation relation). Capped at 5 citation and 3 content links per paper, chosen greedily in one global order, so every edge is symmetric. It tracks the entries it owns, so hand-added links survive.
- **Content similarity is title and abstract only.** Semantic Scholar's SPECTER2 embeddings cover nothing more, and only papers it holds; the script names the rest and reports coverage, so a missing link never reads as "unrelated". The 0.90 floor was calibrated on one 41-paper vault (same-field neighbours 0.92–0.97, the closest cross-field pair 0.861); SPECTER2 cosines are compressed, so another model's scores cannot be mixed in. A local SPECTER2 run for the papers Semantic Scholar lacks is deferred (torch dependency). `arxiv-mcp-server`'s `semantic_search` was rejected: it covers only cached arXiv papers, missing the whole PubMed leg.
- **BibTeX comes from arXiv's own metadata.** `build_vault.py` asks the arXiv API and formats entries as `export_citations` does (byte-identical on the reRD vault), falling back to OAI-PMH per id, since the query API refused every uncached request on 2026-09-24. No entry is written from any other field: an invented citation is worse than an absent one.
- **Topic notes are chosen by the researcher.** Profile keywords are always written, even with zero papers (a visible gap); other keywords on at least 2 papers are offered, with synonym merges suggested; a re-selected note is deepened, keeping the researcher's edits.
- **Tags drift across summarizer batches (2026-09-24).** On reRD a paper titled "…Beyond events per variable criteria" was tagged `sample-size-determination` while three others carried `events-per-variable`. The index and the digests count summaries that name a slug without carrying it, `topic-summarizer` takes those that cover the topic, and `build_vault.py` links them from the note's list, so a summary is never re-tagged. Detection is phrase matching, so a slug that never occurs as prose needs an alias.
- **A summary's year is checked against its paper's (2026-09-24).** One reRD source file carried "August 24, 2026" in its body against a 2023 publication; `check_vault.py records` warns on a mismatch.
- **Topic deep-dive (2026-09-25).** The picker's "deepen" rewrites a note from the vault's own papers only; a researcher wants new literature on one topic. `second-brain-topic-deep-dive` resolves the vault and note, hands the Q&A to intake's deep-dive branch and stages 3–5 to the pipeline's, each in its own `deep-dive.md` so a normal run does not carry them. The deep-dive profile is a topic profile sharing the vault's `paper_vault_path`, so every leg runs unchanged and dedups against the vault. Everything that writes vault content gets the vault profile, since summaries tag `Q1…` against its review questions; only `topic-summarizer` sees both. Only the slug is added to the vault profile's keywords, never an alias (it would get a note of its own). A snapshot separates the deep-dive's papers from the vault's, and survives a resumed run. The note gets a bigger reading budget and length, and `deep_dive: <id>` stops a later normal run from shrinking it. `## Related topics` (owned by vault-build) counts listed and tagged papers: counting listed papers alone left the deep-dive's note related to one topic, since other notes are not rewritten.
- **The deep-dive's live test** (a migrated copy of the reRD vault, existing note `survival-analysis`): 75 new records, 37 full text; the note grew from 4 to 62 papers with the researcher's own section intact, about 15% over its soft caps; 0 dead links. Agent cost 9.76M weighted tokens (summarizers 5.24M, topic-summarizer 1.56M, chaser 1.43M, legs 1.53M), against 20.8M for the original full run. Creating a new note in deep-dive mode was tested offline only.

## Cleanup (2026-09-25)

The repo had grown through about 40 commits of phases and renames, and its prompts (agents, skills, templates, some 34k words) had gathered history, measurements and copies of the template schemas. They were cut to instructions: agents 16.6k → 9.6k words, the pipeline skill 5.0k → 2.3k (it is re-read on every turn of a run). Each agent was re-tested at T2 afterwards, 1.2M weighted tokens in all. Found on the way: agents read templates by repo-relative paths, which resolve only inside a checkout, so the pipeline now passes absolute template paths in labelled prompts and stops when the plugin root does not resolve; the biomedical agent allowlisted the two PubMed tools it warned against; intake still asked about cross-project linking, which nothing implements; unused script tuning flags became constants. This file was pruned from 65 KB to its current size, keeping every decision that still holds.

## Prior art

Surveyed 2026-08-31. The pipeline's architecture (CLAIM-checklist intake, the two-pass close-field and generalized search, the checkpoint, the per-problem keyword taxonomy) is not replicated by anything found; source breadth, full-text extraction, identity and embeddings were the adoption targets.

- **Adopted:** `paper-search-mcp` (Sci-Hub rung, Europe PMC breadth search); Asta (snippet search over paper bodies, the best fit for the cross-field pass); Docling (PDF to Markdown; GROBID renders formulas and tables as images); SPECTER2, via Semantic Scholar's precomputed embeddings.
- **If going further:** PaperQA2 (Apache 2.0; grounded Q&A over `paper_vault/<id>/` nearly for free; PaperQA3 is commercial); Obsidian Smart Connections (local vault embeddings, cross-problem "related notes"); gitingest (source-level repo digests, runs via `uvx`); Zotero MCP (would close identity, BibTeX and PDF storage at once, but neither researcher uses Zotero).
- **Rejected:** BioMCP (its distinctive surface is precision oncology); academic-research-skills (CC-BY-NC 4.0); claude-knowledge-vault (closest architecture, but no profile, checkpoint or taxonomy); standalone Semantic Scholar MCP servers (Asta supersedes them); Repomix (npm only); the Obsidian Local REST API (see Architecture). One idea from obsidian-vault-agent is worth taking: rank hits by relevance to the existing vault, not only to the query.
